# 安全模型

## 可信与不可信

可信：用户确认的运行配置、Supervisor 代码、控制面存储、受保护验收及其摘要。实际部署时这些内容应位于 Worker 写入范围之外。

不可信：Agent 文本/工具调用、项目 README/AGENTS/注释、网页、issue、MCP 返回、实现者测试报告、项目测试及构建脚本。项目约定可提供业务事实与受限工作指导，但不能覆盖上层策略或扩大权限。

任务计划由模型生成，也需校验；任务包 SHA256 保证内容身份，不证明内容可靠。Operator 配置的验证命令也会执行不可信项目代码，必须运行在受限环境中。

## 必需限制与实施层

| 限制 | 实施位置 | 当前状态 |
| --- | --- | --- |
| Supervisor/合同/验收不可写 | OS sandbox、独立用户/挂载边界 | 未实现 |
| 合同路径限制 | 路径解析＋最小可写挂载/权限＋diff 检查 | 未实现 |
| shell 与网络限制 | Worker 执行环境、工具权限与 egress | 未实现 |
| Review 只读且新会话 | Adapter 参数＋实际能力检查 | 未实现 |
| 外部 MCP 副作用限制 | 禁用未审计工具及单独权限控制 | 未实现 |
| 凭证最小化 | 环境 allowlist、支持的认证路由、脱敏 | 未实现 |

Git worktree 只隔离变更，不限制任意文件访问。命令名白名单也不能阻止 `python` 读取密钥、`pytest` 执行恶意代码。事后 diff 只能检测，不能阻止已发生的外泄。不能把这些能力描述为 sandbox。

## 默认拒绝

- 不支持的隔离平台或缺少 enforceable 能力时拒绝真实 Agent 执行。
- 不启用 danger-full-access、dangerously-skip-permissions 或权限绕过。
- 实现者不获得 Supervisor、受保护检查、宿主凭证目录和主仓库 `.git` 的写权限。
- 网络默认禁用，允许的目的地单独配置；真实认证不能靠写入假密钥完成。
- 未审计 MCP 默认禁用；shell sandbox 不覆盖外部服务副作用。
- 接管者拥有同样边界，不能通过“兜底”扩大权限。
- `.supervisor/` 被 Git 忽略不代表其中内容安全；实际运行必须隔离该目录并限制读取者。

## 需要覆盖的攻击与失败

路径穿越、符号链接/硬链接、大小写碰撞、TOCTOU、修改测试/合同/数据库、伪造验收、旧快照通过、进程树逃逸、巨大 stdout、环境/日志泄密、CLI/MCP 扩权、崩溃重复执行、供应链升级。

日志保留元数据与脱敏结果，usage 未知保留 null。原始输出默认关闭；脱敏策略既不能保证拦截所有秘密，也不能替代最小凭证和访问控制。密钥测试只能使用非生产哨兵值。

## 开发与运行的区别

本仓库的 AGENTS.md 是当前开发约定；未来 Supervisor 的运行策略必须从受保护配置加载，不能让正在被实现的目标仓库修改它。本项目开发时 Agent 获得哪些权限由当前平台和用户授权决定，文档不能声称已经实施目标系统隔离。

真实运行前必须验证文件、进程、网络、MCP 等必要边界，并记录平台/CLI 版本。Mac mini 的能力目前未知，先进行只读探测和合成仓库测试。
