# 项目规格 v0.1

## 用户目标

建立可长期使用的通用 Coding Supervisor，把“规划 → 实现 → 独立审核 → 有限返修 → 接管 → 最终验收”自动化。项目业务、Agent、模型和执行机器都可通过明确的配置替换。

用户决定后续开发全部使用Mac mini上的本地模型，包括规划、实现、全新审核、接管和最终验收。云端Codex/Claude兼容接入为可选扩展。保留模型表现数据，速度次于可审计性和正确性。具体流程见LOCAL-MODEL-EXECUTION-PLAN.md。

## 第一版范围

- Python CLI、确定性状态机、版本化 TaskBundle。
- Worker 管理进程，Adapter 解释特定 Agent 的调用和输出。
- Mock Adapter先跑通，再核验本地Hermes及本地角色配置；云端Agent兼容后置、可选。
- 单机 SQLite、结构化事件、文件证据、代码快照摘要。
- 独立测试执行器、受保护验收和绑定快照的审核。
- 可观测的取消、超时、输出损坏、崩溃恢复和权限失败。
- Linux/macOS/Windows 是目标平台；只有在对应平台实际验证后才声明支持。

第一版不含 Web UI、第三个调度 LLM、自动 push、自动升级、模型训练、消息队列、RAG、远程多机调度实现。远程执行边界预留在接口，M5 才实现。

## 系统不变量

1. 核心流程认识角色，不依赖 Agent 名称或业务目录结构。
2. 策略来自独立受保护的配置；Agent、项目文件、网页和 MCP 输出不能增加权限。
3. 任务执行前冻结任务包与可验证基线；更改要求产生新任务版本。
4. Review 必须是 fresh session。记录上下文独立与供应商独立两个维度。
5. 通过必须绑定 task ID、run ID、任务包摘要和代码快照。任何代码变化使旧通过失效。
6. 实现者的退出码 0 或声明通过，都不构成最终验收。
7. 只允许一次主要实现者返修，之后最多一次接管和最终验收；不无限循环。
8. Supervisor 自身、任务包、可信策略和受保护测试对 Worker 不可写。
9. 能力不足或结果不确定时停止，不降低策略或猜测成功。
10. SQLite 状态不等于外部操作完成；恢复须核对副作用和证据。

## 完成标准

M0–M4的必要检查通过，真实本地Hermes/本地模型角色接入有版本和平台证据；所有异常分支有故障注入测试；无关键未解释失败；日志脱敏；用户可从干净基线复现一次完整任务和一次返修/接管路径。M5 的远程 Worker 是可选扩展。

“本地模型通过率”按相同合同、基线、预算和受保护检查统计；缺失或跳过的验收不得计为通过，不把样本数字写成实际测量。
